The previous presentation ended with a positive result at the compatibility-estimation level.

Direct support-NELBO was the rst method that made expert-target compatibility look measurable under the protocol.

But that result was still at the routing stage.
It told us which expert looks most compatible with a target support set, not whether the generated embeddings from that expert are useful for a downstream classi er.

So the translation test is:
I take the support-NELBO ranking, select one or several experts, generate synthetic embeddings, train downstream classi ers, and evaluate only on the held-out target
set.

This asks whether compatibility estimation survives the full downstream pipeline.

I do not treat the low downstream result as one failure.

I split it into three possible failure points.

First, the representation may not contain enough signal.
Before testing any CVAE or router, the real embedding space must contain class-relevant and domain-relevant structure.
If DINOv2 embeddings are noisy or insu cient for histopathology, generation and routing cannot recover the lost signal.

Second, the CVAE may not preserve the useful structure during generation.
Even if the real embeddings are useful, the CVAE may fail to preserve the class-conditional geometry after sampling.
This is a legitimate bottleneck because VAEs/CVAEs optimize a variational objective, not downstream balanced accuracy directly.

Third, the signal may exist, but sparse top-1 routing may select the wrong component.
This is exactly the sparse expert-selection problem: sparse routing is e cient, but it requires accurate routing; otherwise, useful complementary experts are discarded.

The next slides test these bottlenecks one by one.

The key point is that the 0.677 oracle does not end the analysis.

It tells me the sparse generated-expert setup has a ceiling.

To locate the ceiling, I rst test whether the foundation embedding space itself is too noisy.

The PCA64 reconstruction upper reaches 0.862, so the information needed for the downstream task is still present.

Therefore the failure is not caused by the feature representation alone; it is introduced later by CVAE generation, class preservation, or sparse expert routing.

                                              Check 3: Sparse routing
                                              Is Top-1 selection too brittle?




                                              Stephanus Park, 04.06.2026 — Experiments continued                (Yadav et al., 2025)

                                                                                           10




After the CVAE generation check, I wanted to know whether the problem is unavoidable for synthetic embeddings, or whether it is speci c to the CVAE generator.

The PCA64 GMM is a simpler diagnostic sampler. It removes the CVAE encoder-decoder bottleneck and asks: if I model the source distribution more directly in PCA64
space, can synthetic embeddings support downstream classi cation?

The answer is yes. The selected GMM reaches 0.807, and the diagnostic oracle reaches 0.844. So the downstream pipeline itself is not doomed. A simpler sampler can
preserve enough geometry to cross the 0.80 gate.

But the GMM is not the thesis method. It is a diagnostic control. It tells me that useful synthetic distributions are possible, and that the remaining CVAE problem is not
only “which expert do I select”, but also how much useful structure each generated component preserves.

This motivates C6.3. Instead of trusting one sparse CVAE-generated expert, C6.3 keeps multiple frozen CVAE components, trains component-speci c classi ers, and
combines their probabilities with a geometric ensemble.

The key connection is: the GMM result shows that strong synthetic downstream utility is achievable when the generated distribution is clean enough. C6.3 asks whether I
can recover part of that bene t while staying inside the CVAE/MoErging setting by reducing sparse-routing risk.

The result is 0.814 BACC. So the synthesis is: sparse top-1 routing is too brittle, but dense post-hoc CVAE composition can recover enough complementary signal to
cross the utility gate.

                                              Comparison of aggregation strategies




                                              Stephanus Park, 04.06.2026 — Experiments continued                 (Yadav et al., 2025)

                                                                                           11




This slide isolates the aggregation rule inside the dense CVAE composition result.

Up to this point, the story was: representation is not the main bottleneck, generation quality matters, and sparse top-1 routing is too brittle. C6.2 already responds to that
by avoiding one selected expert: it trains component-speci c classi ers and averages their probabilities.

Here, C6.3 changes only the nal aggregation rule. Instead of arithmetic probability averaging, it uses geometric pooling, which is more consensus-sensitive. So this is
not a new generator and not a new compatibility estimator. It asks whether dense CVAE composition should behave more like a consensus across components.

The plot shows that geometric pooling improves mean BACC by about +0.026. Four out of ve centers improve: center 1 gains the most, about +0.051, and centers 0, 3,
and 4 also move upward. Center 2 slightly decreases by about -0.006, so the gain is not perfectly uniform.

The synthesis is that dense composition is useful, but the aggregation rule matters. Simple averaging already reduces sparse-routing risk, but geometric pooling recovers
more utility by rewarding agreement across frozen CVAE components and reducing the in uence of weaker or overcon dent members.

This supports the thesis-facing claim cautiously: the strongest result is not better top-1 routing, but post-hoc dense composition of independently trained CVAE experts.
