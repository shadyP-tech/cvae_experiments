# MIDOG++ Ensemble-Endpoint Proxy-Information Audit

## Status and purpose

`midogpp.oracle.uniform_b_v2_consumed_validation_utility_aligned_ensemble_endpoint_proxy_information_audit.v1`
is an implemented, registered Stage-90 diagnostic. It tests whether a small,
predeclared family of label-free support features contains cross-target
information about exact-nine ensemble BACC utility.

The audit is a response to the completed ensemble-endpoint router result: the
exact-nine endpoint removed the former seed-aggregation mismatch, but the
two-case absolute probability-shift scalar did not rank useful source tails.
This experiment therefore tests proxy information before another router or
policy is designed.

No canonical result exists until the workstation run completes and validates.
The run uses consumed MIDOG++ validation cases and is always
`EXPLORATORY_CONSUMED_DATA_ONLY`.

## Independent replay and label boundary

The completed Stage-90 router output is not an input. It contains scored
endpoints, action choices, and oracle products and is catalogued as terminal.
This audit instead receives its own single-consumer aliases over the immutable
label-free validation cache and manifest, regenerates its own source streams
and predictions, and creates a global development prediction seal before any
development label is opened.

Features use only two fixed support cases and support-role probabilities.
Evaluation probabilities, support labels, target actions, target labels,
Stage-50/60/70 outputs, and every earlier Stage-90 output are forbidden.
Development labels are opened only after the 504 proxy rows have been sealed,
and are used only to score the candidate response.

## Frozen proxy screen

The modeled response is one exact-nine probability-ensemble BACC delta for
each legal `(H,q,e)` candidate, for 504 observations. The 4,536 seed-cell
utilities remain descriptive and cannot enter fitting or uncertainty.

Seven fixed families are evaluated with ridge alpha `1.0` and no tuning:

- equal-union null;
- metadata-only control;
- absolute-shift control;
- compact reconstruction/KL/log-MMD distributional features;
- compact signed-margin/threshold-flip/entropy-change features;
- a three-feature metadata/log-MMD/signed-margin hybrid;
- a within-query cyclic permutation control for the directional features.

Every learned fold excludes `H`, `q`, and `e` from all three training roles:
outer target, query, and candidate source. This leaves exactly 120 training
rows. Learned centering and scaling are fit inside the fold.
Ridge loss is cluster-weighted by the `(outer target, query)` pair, never by
candidate or seed rows.
The reconstruction/KL/MMD z-scores are a separately declared label-free
within-candidate-list transform and use no utility or evaluation label.

Results are summarized first within the 72 nested `(H,q)` groups and then at
the nine independent outer-center units. A candidate family screens positive
only if its center-level 95% intervals pass all predeclared Spearman,
pairwise-ordering, and normalized-regret gates and its mean regret beats all
three controls. Even a positive screen cannot authorize an action, policy,
Stage-60/70 input, promotion, or deployment; it only justifies designing a
fresh-data proxy confirmation.
